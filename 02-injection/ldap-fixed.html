What changed?

Before inserting user input into the LDAP filter string, all LDAP special characters are escaped according to RFC 4515.

The characters \ * ( ) NUL are replaced with their \xx escape sequences. After escaping, these characters are treated as literal data values by the LDAP server — they cannot alter the filter structure.

The escaping function (RFC 4515)

/**
 * Escapes special characters in LDAP search filter assertion values.
 * Per RFC 4515, the following characters must be escaped:
 *   \  (U+005C) → \5c   ← MUST be escaped FIRST to avoid double-escaping!
 *   *  (U+002A) → \2a
 *   (  (U+0028) → \28
 *   )  (U+0029) → \29
 *   \0 (U+0000) → \00
 *
 * @param {string} input - Raw user input
 * @returns {string} Input safe to insert into an LDAP filter value position
 */
function escapeLdap(input) {
  return String(input)
    .replace(/\\/g, '\\5c')  // backslash FIRST — prevents double-escaping
    .replace(/\*/g,  '\\2a') // asterisk (wildcard operator)
    .replace(/\(/g,  '\\28') // open parenthesis (opens filter condition)
    .replace(/\)/g,  '\\29') // close parenthesis (closes filter condition)
    .replace(/\0/g,  '\\00'); // null byte (can truncate in some LDAP libs)
}

// Usage:
function buildSafeLdapFilter(username, password) {
  const safeUsername = escapeLdap(username);
  const safePassword = escapeLdap(password);
  return `(&(uid=${safeUsername})(userPassword=${safePassword}))`;
}

// Attack input:    *)(uid=*))(|(uid=*
// After escape:    \2a\29\28uid=\2a\29\29\28|\28uid=\2a
// Safe filter:     (&(uid=\2a\29\28uid=\2a\29\29\28|\28uid=\2a)(userPassword=x))
// LDAP looks for:  A user whose uid LITERALLY equals that escaped string → no match!
