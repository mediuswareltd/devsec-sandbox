About this demo

This page simulates an LDAP-backed login that is vulnerable to LDAP injection. No real LDAP server is used — the filter construction and injection logic run entirely in JavaScript so you can see the attack clearly.

The application builds an LDAP filter string by concatenating user input directly. An attacker can inject LDAP syntax characters to break out of the expected filter structure and construct a condition that always evaluates to true.

Open ldap-fixed.html to see the safe version.

The vulnerable code

// VULNERABLE — never do this!
function buildLdapFilter(username, password) {
  // User input is directly concatenated into the LDAP filter string.
  // LDAP special characters in username/password break the filter structure!
  return `(&(uid=${username})(userPassword=${password}))`;
}

// Normal filter:   (&(uid=alice)(userPassword=wonderland))
// Injected filter: (&(uid=*)(uid=*))(|(uid=*)(userPassword=x))
//                       ^--- injected! closes the AND, adds OR always-true

LDAP filter syntax primer

SyntaxMeaning
(&(a)(b))AND: both a and b must be true
(|(a)(b))OR: at least one of a, b must be true
(!(a))NOT: a must be false
(uid=alice)Attribute equality: uid equals "alice"
(uid=*)Wildcard: uid has any value (matches all)
(uid=a*)Prefix wildcard: uid starts with "a"

Special characters * ( ) \ NUL have syntactic meaning in LDAP filters. When they appear unescaped in user input, they alter the filter structure.
