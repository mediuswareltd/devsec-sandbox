What changed?

Before building the query, this version validates that both username and password are strings.

If either value is an object (e.g. {"$gt":""}), the login is rejected immediately with a 400 Bad Request error. The query is never executed.

The safe code

// FIX: Type validation before querying
function safeLogin(username, password) {

  // Verify that both inputs are strings, not objects or other types.
  // This blocks MongoDB operator injection, because:
  //   typeof { "$gt": "" }  === 'object'  → rejected!
  //   typeof "secret123"    === 'string'  → allowed

  if (typeof username !== 'string' || typeof password !== 'string') {
    throw new Error('Invalid input: username and password must be strings.');
  }

  // Now it is safe to query — both values are guaranteed to be plain strings.
  // MongoDB will compare them literally, never as operators.
  return db.users.findOne({ username: username, password: password });
}
